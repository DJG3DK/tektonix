## 1. Infrastructure, packaging and CI

### I1. The nginx `/_review/` location adds the review secret for anonymous callers

**Severity:** critical. **Kind:** security. **Since:** `b046c0a` (2026-09-18).
**Files:** `install.sh` (the vhost heredoc: the `location /_review/` block with `proxy_set_header X-Review-Secret $REVIEW_CONTROL_SECRET;`), `INSTALL.md` (§ review dashboard behind nginx), `tests/test_docs_are_true.py` (it *requires* the block), `services/agent-review/server.js` (`requireControlSecret`; the merge route's `req.body.force`).

The block proxies `/_review/` straight to `127.0.0.1:4100` and adds the
secret to every request. Its comment says the operator "reached this host
through the same login that already gates /". Nothing gates `/` at nginx
level: the login lives inside the app, and this location bypasses the app.
`requireControlSecret`'s `Sec-Fetch-Site` check stops only browsers; `curl`
sends no such header.

On any `install.sh --domain` host, an anonymous caller can:

```
curl -X POST https://DOMAIN/_review/api/projects/<name>/merge \
  -H 'content-type: application/json' -d '{"force":true}'
```

That merges unreviewed work, and pushes it. The same caller can reach
`/restart` (pm2 apps) and read `/api/projects` and `/diff` (source diffs).
`certbot --nginx` copies the block into the 443 server. The vhost file is
created by `sudo tee` with mode 0644, so the secret is also readable by
every local user.

**Shape of the fix**

- Delete the `location /_review/` block. `location /` already reaches the
  agent, and `agent/routers/review_proxy.py` serves `/_review/` behind
  `require_full_auth` and injects the secret itself.
- Delete the "add it by hand" snippet in `INSTALL.md`.
- Invert the `test_docs_are_true.py` assertion: `install.sh` must not
  contain `X-Review-Secret` or a `proxy_pass` to `:4100`.
- Existing installs keep the hole, because `install.sh` leaves an existing
  vhost alone. Add a `scripts/doctor.py` check that fails if
  `/etc/nginx/**` contains `X-Review-Secret`. Add a CHANGELOG / release
  note telling operators to delete the block and rotate
  `REVIEW_CONTROL_SECRET`.
- Add a `SECURITY.md` line: the review services are reachable only through
  the agent's authenticated proxy.

**Do not touch:** `review_proxy.py`, `requireControlSecret`, or the
timing-safe compare.

### I2. `install.sh` writes a router URL without `/v1`

**Severity:** high. **Kind:** bug. **Since:** `19e568f` (litellm removal, 2026-09-16).
**Files:** `install.sh` (`MODEL_ROUTER_URL=http://127.0.0.1:4001` in the `.env` heredoc), `.env.example` (has `/v1`), `docker-compose.yml` (`http://router:4001/v1`), `services/model-router/router/app.py` (only `/v1/*` routes), `agent/health.py` (liveness strips the path).

The OpenAI SDK appends `/chat/completions` to `base_url`, and the router
404s without `/v1`. Every model call on a fresh host install fails, while
`/api/health` stays green, because liveness strips the path.

**Fix:** write `/v1`. Optionally, `agent/config.py` normalises a missing
`/v1` with a startup warning.
**Test:** extend `tests/test_bundle_router_config.py` to parse `install.sh`'s
heredoc and require `/v1`. A `doctor.py` probe of `POST {url}/chat/completions`
should expect something other than 404.

### I6. `deploy-poll.sh` never retries a failed build

**Severity:** medium. **Kind:** bug. **Files:** `scripts/deploy-poll.sh`, `docs/runbooks/deploy-poll.md`. (The backend report raised it independently as B7.)

`git pull --ff-only` runs *before* install, build and `pm2 restart`. After
any of those fails, the next tick sees `HEAD == origin/$BRANCH` and prints
"up to date". Production stays on the old build indefinitely.

Also:

- `DIRTY=… | awk '{print $2}'` mis-splits renamed paths and paths
  containing spaces.
- `LOCK_FILE` uses only the basename, so two projects with the same name
  share a lock.

**Fix:** write a `deployed_sha` state file only after the restart succeeds,
and compare `REMOTE` against it instead of `HEAD`.
**Test:** in `tests/test_deploy_poll.sh`, a `BUILD` that fails once must be
retried on the next run.
**Do not touch:** `flock`, `--ff-only`, KEEP/RESET_DIRTY.

### I7. The bundle has no backup path, and its volume docs are wrong

**Severity:** medium. **Files:** `scripts/backup.sh`, `docker/README.md` (says "four named volumes"), `INSTALL.md`, `docs/backup.md`, `docker/postgres/init-secrets.sh`.

  `routerconfig`, `bundlesecrets`, `agentdata`).
- Document restore.

**Test:** a `test_docs_are_true` check that the README's volume list equals
compose's `volumes:` keys.

### I9. The release workflow uses mutable action tags beside the updater signing key

**Severity:** medium. **Kind:** supply chain. **File:** `.github/workflows/release.yml`. (Merges D12.)

Every `uses:` is a tag: `actions/checkout@v7`, `docker/*@v4/v7`,
`tauri-apps/tauri-action@v1`, `swatinem/rust-cache@v2`, and
`dtolnay/rust-toolchain@stable`, which is a branch.

The `app-windows` job:

- receives `TAURI_SIGNING_PRIVATE_KEY` and its password;
- has `contents: write`;
- inherits the workflow-level `packages: write`.

Auto-update defaults to on (`Prefs::default`). Whoever can move one of
those tags can therefore sign an update for every desktop install. There is
no GitHub Environment protecting the secret, and no tag ruleset for `v*`.

**Fix:**

- Pin every `uses:` by full commit SHA with a `# vX.Y.Z` comment.
  Dependabot's github-actions entry keeps SHA pins current.
- Move `packages: write` to the `images` job.
- Put the signing secrets in a `release` Environment with a required
  reviewer.
- Add a tag ruleset for `v*`.

**Test:** a Python test that every `uses:` in `release.yml` matches `@[0-9a-f]{40}`.
**Do not touch:** the `env:` indirection in `run:` steps. It is correctly
injection-safe.

## 2. Review gate (`services/commit-reviewer`, `services/agent-review`, `agent/review_sandbox.py`)

### R1. The post-merge "verdict not cleared" handler calls an undefined `log`

**Severity:** medium. **Kind:** bug. **Since:** `4b28a2e`.
**File:** `services/agent-review/server.js` (merge route, the `catch` around `clearReviewState`).

```js
} catch (e) {
    log(`[${req.params.name}] merged, but the review verdict was not cleared: ${e.message}`);
}
```

There is no `log` in module scope; the only one is a local `const log = await git(…)` in
another handler. When clearing fails, a `ReferenceError` reaches the outer
catch. Then:

- the caller gets 409 `log is not defined` after `merge --ff-only` already
  landed;
- **the push to origin is skipped**;
- the READY record stays, which is the outcome `4b28a2e` existed to
  prevent.

**Fix:** `console.log`.

### R2. Host `mountSpecs` mounts whatever live path an agent-committed symlink names, including the live root

**Severity:** high on host installs. **Kind:** security.
**File:** `services/commit-reviewer/sandbox.js` (`isInside` treats `rel === ''` as inside; the symlinked-`node_modules` loop; the generated-dirs loop).

A worktree entry `node_modules -> <live>` yields the spec
`{src: <live>, dst: <live>}`, which becomes `-v <live>:<live>:ro`. A check
script can then read `<live>/.env`, and its output flows into the check
output, the review and the agent's feedback.

The bundle's receiving side, `agent/review_sandbox.py` `_checked_mounts`,
already refuses this: no live root, and same-path mounts must be live
`.git`, contain a `node_modules` segment, or be a configured generated
directory. Host mode runs `docker` itself and has no second check.

`git_commit`'s deny-list matches the substring `"node_modules/"`, so a
symlink *named* `node_modules` (no trailing slash) passes it.

**Fix:** parity with `_checked_mounts`:

- refuse `target === path.resolve(cfg.live)`;
- in the symlink loop, require a `node_modules` path segment in the
  resolved target;
- in the generated loop, require
  `target === realpath(path.join(cfg.live, g.dir))`.

Also make the `git_commit` deny-list match a `node_modules` path segment,
not the substring.

**Test:** `tests/test_reviewer_sandbox.js` with worktree symlinks pointing
at `cfg.live`, `cfg.live/backend` and `cfg.live/x/node_modules`. Expect no
spec, no spec, and one spec.
**Do not touch:** the dangling-link skip, `:ro`, and the template
allowance.

### R3. In the bundle, check tooling can come from a `node_modules` the task agent shares by hardlink

**Severity:** high. **Confidence:** medium. **Kind:** security (checks "pass" without running).
**Files:** `services/commit-reviewer/node-modules-source.js` (`[['live', …], ['template', cfg.sandbox]]`), `sandbox.js` (template allowance), `agent/review_sandbox.py` (`from_template`), `agent/workspaces.py` (its own docstring: an in-place edit of a `node_modules` file "changes it for the template and every task linked to it").

reviewer borrows the template's. A task command that rewrites
`node_modules/.bin/<linter>` in place therefore changes the tool the
reviewer runs, and lint or tests exit 0 having checked nothing. The
read-only mount does not help, because the write happens before the

**To confirm:** in a bundle task, run

commit that has a lint error.

**Fix (pick one):**

- the reviewer runs `npm ci` into a cache keyed by the lockfile hash;
- verify package integrity against the lockfile before borrowing;
- `workspaces.py` stops hardlinking `.bin/**` and `**/bin/**`.

**Test:** modify a template file through a hardlink, then require that the
reviewer refuses the source or re-provisions.
**Do not touch:** the live-first preference and foreign-platform detection.

### R4. The `secretFiles` copy follows committed symlinks, so a review credential can overwrite live `.env`

## 3. Desktop app and release (`app/`, `release.yml`)

Verified against the locked crate sources (tauri 2.12.0, updater 2.13.0).
`tauri-2.12.0/src/webview/mod.rs` rejects app commands from a remote
origin unless a permission grants them (`plugin_command.is_some() || has_app_acl_manifest || !is_local`).
**So the console page at `:8100` cannot call `stack_password`,
`settings_save` or the other app commands.** It *can* use every plugin
permission in `default.json` (D5).

### D1. The console's "Control panel" button can never work

**Severity:** medium. **Kind:** bug. **Files:** `frontend/src/components/TitleBar.tsx` (`void tauri()?.core?.invoke?.("open_panel")`), `app/src-tauri/build.rs` (plain `tauri_build::build()`, no app manifest), `capabilities/default.json`.

With no app manifest, no capability can grant `open_panel` to the remote
origin, so the call is rejected. The `void` swallows the rejection, and the
tray becomes the only way back. The CHANGELOG advertises the link.
`TitleBar.test.tsx` mocks `invoke`, so the test passes regardless.

**Fix:**

- Add an `AppManifest` in `build.rs` listing every command.
- Split the capability into `panel.json` (local; every app command plus the
  plugins) and `console.json` (remote; `allow-open-panel` plus the window
  controls).
- Once a manifest exists, every command needs a local permission, or the
  panel breaks.

**Test:** a Rust test with `tauri::test::mock_builder` / `get_ipc_response`:
`open_panel` from `http://localhost:8100` succeeds, and `settings_save`
from there is rejected.

### D2. The first-password flow can lock the operator out

**Severity:** high. **Kind:** bug / UX. **Files:** `app/src/main.js` (checks only `length < 12`), `app/src-tauri/src/stack.rs` `set_first_password`, `scripts/show_initial_password.py` (deletes the file once shown), `agent/auth.py` `validate_password_strength` (also needs lowercase, uppercase and a digit).

`set_first_password` reads, and thereby **deletes**, the one-time password;
then signs in; then posts `change-password`. A 20-character all-lowercase
passphrase passes the panel, is refused by the agent, and the one-time
password is gone:

- "Show first password" finds no file.
- Resubmitting does nothing, because `installed_version` is now set.

Recovery means email reset (rarely configured on a desktop) or wiping the
database volume.

**Fix:**

- Mirror `validate_password_strength` in `main.js` and in Rust *before*
  reading the one-time password.
- On any failure after the read, return the one-time password to the panel
  so the operator can finish by hand.

**Test:** a Rust `password_problem()` unit test, plus a Python test pinning
the JS and Rust rules to `auth.validate_password_strength`.
**Do not touch:** "nothing stored here".

### D3. The updater orders `-rcN` tags as text, stranding most RC installs

**Severity:** high. **Kind:** bug. **Files:** `stack.rs` (updater built without `version_comparator`), `release.yml` (tag-stamped version).

The plugin's default comparison is semver, and semver compares
pre-release identifiers like `rc14` / `rc9` as strings. So
`0.9.0-rc14 > 0.9.0-rc9` is false. An rc2–rc9 app sees rc10–rc22 as older.

The tag-stamped version arrived only in `5e6d872` (rc13), so rc1–rc12
binaries all report `0.9.0` and will not take the stable `v0.9.0` either.

**Fix:**

- One shared `updater(app, tag)` that sets
  `.version_comparator(|cur, rel| newer_than(rel, cur))`, using the stack's
  numeric `version_key`.
- Or move future tags to semver-correct `-rc.N`.
- Tell rc1–rc12 testers in the release notes to reinstall by hand.

**Test:** a table test showing the comparator and `newer_than` agree
(rc9→rc10, rc19→rc20, rc→release, release→next rc).

### D4. After a stack-only update, new images run under the old app's compose file

**Severity:** high. **Kind:** correctness. **File:** `stack.rs` (`prepare` copies compose from the app's resources; `auto_update_pass` updates the stack first; `ensure_own_release` does not re-`up` when the shipped compose changes).

Example: rc17 added `SANDBOX_CPUS` / `SANDBOX_MEMORY` to the agent's
environment. An rc16 app running rc17 images never passes them. The app
half of an update is often deferred (busy, window in use, or D3), so the
two drift.

**Fix:** tie the stack target to the app's own tag and update the app
first, or record the shipped compose file's hash in `version.json` and
re-`up` when it changes.
**Test:** extract a pure decision function (record, local image id, app
tag, latest tag, busy, prefs, compose hash → action) and table-test it.
D7–D10 need the same extraction.

### D5. The console origin gets far more than window controls

**Severity:** medium. **Kind:** security (defence in depth). **File:** `capabilities/default.json`.

One capability covers the panel and the remote `:8100` origin:

- `process:default` (exit and restart);
- `updater:default` (check, download, install);
- `dialog:default`;
- `opener:default` (open any http(s) URL);
- the full `core:default` (tray and menu construction, `event:allow-emit`).

The capability's own description says "the console page gets the window
controls and the two page switches". The console renders model-produced
text, so its CSP is the only barrier left.

**Fix:** the D1 split. The remote capability gets exactly
`core:window:allow-{start-dragging,minimize,toggle-maximize,close,is-maximized}`
plus `allow-open-panel`.
**Test:** a Python test that the remote capability's permission set equals
that list.

### D6. Two tray icons, one inert

**Severity:** medium. **Kind:** UX. **Files:** `tauri.conf.json` (`app.trayIcon`), `lib.rs` `build_tray`.

Tauri creates the config tray itself, with no menu and no handler. Then
`build_tray` adds a second one. **Fix:** delete `app.trayIcon`, or have

### D7. Stack operations are not serialised, and the first automatic pass races the first install

**Severity:** medium. **Files:** `lib.rs`, `stack.rs`.

The automatic pass starts 120 s after launch. `write_version` runs only
after all pulls finish, so during a first `stack_install` (about 3 GB) the

overlap the six-hourly pass the same way.

**Fix:** a managed `tokio::Mutex` held by install, up, down, update and the
pass; the pass uses `try_lock`. The pass also skips until settings and a
record exist.

### D8. The automatic pass restarts a stack the operator stopped

**Fix:** `up` only if the agent answered before the pull. Otherwise pull

### D9. An agent that does not report `busy` counts as idle

**Severity:** medium. **File:** `stack.rs` (`agent_busy`).

## 5. Agent core, tools and model plumbing

Covers `agent/deep_agent.py` and its split modules, `agent/middleware/*`,

### A1. The delete gate's variable expansion mis-resolves ordinary shell

**Severity:** medium. **File:** `agent/deep_agent.py` `_ASSIGNMENT_RE`, `_expand_local_assignments` (lines 483–508).

Since the 2026-09-29 change, `_deletions_that_lose_work` first substitutes
"the plain assignments made earlier in the same command". The code does
not do that. It collects **every** regex match anywhere in the command
into one dict, the **last** one wins, and then substitutes `$NAME` and
`${NAME}` everywhere, in any position, inside any quoting. So:

- `P=/tmp/x; rm -rf "$P"; P=src` reads as `rm -rf "src"`, which asks.
  That is a false positive, but harmless.
- `P=src; rm -rf "$P"; P=/tmp/x` reads as `rm -rf "/tmp/x"`, which is
  scratch, so the delete of `src` **is not asked about**.

Reproduced on this VM with `_deletions_that_lose_work`. Each of these
returns `[]` (nothing lost), although the shell deletes `src` or nothing
at all:

| Command | What the shell deletes |
|---|---|
| `P=src; rm -rf "$P"; P=/tmp/x` | `src` |
| `for P in src; do rm -rf "$P"; done; P=/tmp/x` | `src` |
| `P=src; rm -rf '$P'; P=/tmp/x` | a file literally named `$P` (the gate substituted inside single quotes) |
| `P=/tmp/x true; rm -rf "$P"` | `$P` is unset for `rm`, since the prefix assignment belonged to `true` |

Reading the code, the same happens in two more cases. An `export P=/tmp/x`
that follows the use also wins. And when `read P` or `P+=…` changes the
value before the use, the gate still uses the earlier literal. A subshell assignment such as
`(P=/tmp/x)` is not matched, because the regex's lookahead excludes `)`,
so that shape is correctly reported.

The gate is a guard against the agent's own mistakes, not an adversary,
so this is medium, not high. But it is exactly the mistake class the
gate exists for: a variable that holds the wrong path.

**Fix:** walk the command's top-level segments in order. Bind a name only
at a plain `NAME=literal` segment that comes *before* the use. Poison the
name (so the target stays unreadable and asks) on any other writer:
reassignment, `read`, `for`, `+=`, `export`, or a prefix assignment. Never substitute inside single quotes. Pin each shape above in `tests/test_auto_approve_gate.py`. At minimum,
pin the "reassigned after the use" case.
**Do not touch:** the `_ALWAYS` "unreadable means ask" rule, or the
`.git` special case.

### A2. Delete forms the gate does not recognise

**Severity:** low. **File:** `agent/deep_agent.py` `_deletions_that_lose_work`.

The gate does not recognise `env rm …`, `xargs rm`, `sh -c 'rm …'`,

### A3. The empty-reply retry swallows `BudgetExceededError`

**Severity:** medium. **File:** `agent/middleware/empty_reply.py` (lines 181 and 196: `except Exception as e: # noqa: BLE001 -- see _retry_failed`).

`BudgetExceededError` (`budget_guard.py:84`) subclasses `Exception`. When
the budget guard refuses the retry call, `_retry_failed` logs it as a
failed retry, and the loop moves on to the next attempt, which the guard
refuses again. The original empty reply is returned, and the conversation
continues past its ceiling until the next model call outside this
middleware raises. It is the same for any other control exception a
handler raises (cancellation raises `BaseException`, so it is unaffected).

**Fix:** `except BudgetExceededError: raise` before the broad catch, in
both the sync and async paths, and a test that a guard refusing the retry
ends the task.

### A4. A planning turn's quiet retry runs on the coder; with reasoning already off it pays twice

**Severity:** low. **Files:** `agent/deep_agent.py` (lines 1046, 1065–1074, 1311–1317), `agent/middleware/empty_reply.py` `_attempts`.

The coordinator's empty-reply middleware sits inside `PlanCodeModelMiddleware`,
which puts the planner on a thread's first turn. Its `quiet_model` is
`quiet(coder_role, …)`. So an empty *planner* reply is retried as "the same
seat without reasoning" on the coder's model, which is a different seat.
And `coordinator_model` is built with `reasoning=coder_reasoning()`. When
that is already off, the quiet retry is the identical request again: a
paid call that cannot answer differently. **Fix:** pick the quiet model
from the model the request actually carries (`request.model`), and skip
the quiet attempt when that model's reasoning is already off.

### A5. Middleware state is shared across parallel `task` calls; the `budget_guard` docstring is false

**Severity:** low. **Files:** `agent/middleware/budget_guard.py` (lines 54–57), `agent/middleware/empty_reply.py` (`self.retries`, `self.quiet_model`).

The `budget_guard` docstring says that subagents "run synchronously … only
one model call for the whole task is ever in flight at a time". The
coordinator can emit several `task` tool calls in one message, and
LangGraph runs them concurrently. So `BudgetTracker` updates can
interleave, and B17's shared `retries` count is shared across concurrent
subagents. The spend check still runs before each call. An overshoot is
bounded by one call per parallel branch, not unbounded. **Fix:** either set
`parallel_tool_calls=False` on the coordinator (simplest, and it matches
the docstring), or give the tracker a lock and keep per-invocation retry
state. Then correct the docstring.

### A6. Episode-recall `rank` is `None` for exactly the cases it was added to measure

**Severity:** medium (it silently corrupts the data a pending decision rests on). **File:** `agent/episode_recall.py` (`TOP_N = 5`, `_LAST_REFS`, `_remember`, `record_use`).

The comment above `_LAST_REFS` says the rank exists so that "a used
episode at rank six or worse says ordering is the problem; one that was
never offered says the candidate pool is". But `record_query` stores only

- The key is `(task_id, repo)`. A use of an episode from another repo that
  a cross-project search offered looks up the wrong key, and is `None`.
- Each search replaces the entry. An episode offered by search 1 and read
  after search 2 is `None`.
- `_remember` evicts in insertion order, not least-recently-used. A
  long-lived task's entry is evicted first.

**Fix:** remember every returned ref (only the *written* `refs` list
needs to stay at `TOP_N`), key by `(task_id, ref)` or keep a per-task
union with the first rank seen, and use an `OrderedDict` with
`move_to_end`. Log `rank: null` and `offered: false` as separate fields.
Pin "rank seven is recorded as seven".

### A8. A cancelled router stream records no ledger line; a chain that fails entirely returns an empty 200

**Severity:** medium. **File:** `services/model-router/router/app.py` `_streamed` (lines 327–372).

The success `ledger.record(...)` runs only when the `async for` finishes.
When the client disconnects mid-stream (a stall-watchdog abort or a
cancelled task), Starlette closes the generator with `GeneratorExit` or
`CancelledError`. Both are `BaseException`, so the `except Exception`
does not run either, and **no line is written**. The tokens were spent,
and the agent's `router_ledger` reconciliation cannot see them.

When every deployment fails before the first byte, `body_iter` logs and
returns, and the client receives `200 text/event-stream` with an empty
body. The buffered path returns 502 with the chain, and the agent's retry
logic keys on that.

**Fix:** wrap each attempt in `try/finally` and record with
`error_detail="cancelled"` when it did not complete. Peek the first chunk
before constructing the `StreamingResponse`, so a total failure can
still return the buffered path's 502. Test both in
`services/model-router/tests`.

### A9. Router ledger I/O blocks the event loop, and the trim is not atomic

**Severity:** low. **File:** `services/model-router/router/ledger.py` (`path.write_bytes(keep)` at line 121).

`record` is called from the async stream generator and appends
synchronously, under a thread lock, on the event loop. Past the 50 MB cap,
`_trim` reads the whole file and rewrites it in place, on that call, so
every stream in the process stalls while it does. A crash mid-write
truncates the ledger. **Fix:** write to a temporary file and `os.replace`,
and run `record` through `to_thread` (or a single writer task).

### A10. The SWE-bench stop tests patch the global `subprocess.Popen` (root cause of T6)

**Severity:** low. **Files:** `tests/test_swebench_api.py` (lines 231 and 248), `agent/routers/swebench.py` `_remove_run_containers` (lines 501–511, 543).

a real `docker ps` / `docker rm -f` on the developer's machine.

**Fix:** in the tests, patch `sw._remove_run_containers` (or

`pytest -W error::pytest.PytestUnhandledThreadExceptionWarning tests/test_swebench_api.py`.

### T2. `test_clone_on_add` is not hermetic from the user's global git config

**Severity:** low. **File:** `tests/test_clone_on_add.py::test_a_token_never_reaches_the_stored_remote`.

### T4. The sandbox-image tests trust whatever `tektonix-sandbox:latest` is present

## 9. What is in good shape (do not regress)

- **Authorization survived twelve seam moves.** Route inventory plus
  `test_repo_scope.py` stayed green, and no handler lost a
  `check_repo_access`, `require_admin` or rate limit.
- **Task and planning routes.** Repo resolution fails closed. Planning
  WebSockets authenticate and apply `forced_screen_block` before
  `accept()`. Merge, approve and edit run under `_claim_run_slot`.
- **`review_proxy.py`.** Admin-only; strips a caller's `X-Review-Secret`
  before adding its own.
- **Bundle review sandbox.** `_checked_mounts` validation, cap-drop and
  limits, a network allow-list, per-run restricted Postgres roles, an
  `internal: true` checks network, and a rotated superuser.
  `/run` streams with cancel-on-disconnect.
- **Merge gate core.** READY + full-SHA `lastReviewedSha === tipSha` + no
  `inProgress` + `--ff-only`, and every git call runs with hooks off. R6
  only closes the gap after the comparison.
- **Fail-closed review paths.** A missing secret becomes a failing check;
  a missing control secret refuses delegation; reviewer exceptions write a
  harness record.
- **Updater trust.** Real minisign pubkey (pinned by
  `test_desktop_app.py`), https endpoints, per-release manifest, no
  downgrade.
- **Desktop mode.** Only the app writes `TEKTONIX_DESKTOP`. The first
  password is never stored, and there is no token in the web UI.
- **No shell in the desktop app.** docker, compose and git calls are argv
  vectors; `CREATE_NO_WINDOW` is set.
- **Release workflow.** No `${{ }}` inside `run:`; no
  `pull_request_target`; draft-then-publish; a skip when already
  published.
- **Bundle secrets.** Generated per install from `/dev/urandom`,
  `sk-local-dev` refused, atomic writes, `*_FILE`. Host `.env` files are
  created under `umask 077`.
- **Git identity** reaches only `GIT_AUTHOR_*` / `GIT_COMMITTER_*`
  environment variables, never git config. `_format_value` rejects CR, LF
  and NUL.
- **Actions ship gate.** Pins the head SHA, force-pushes only the task
  branch, opens PRs idempotently, and names every skip reason.
- **Agent core.** `safe_path` handles the `/root` vs `/rootx` prefix case;
  `_safe_base_env` passes exactly the four git identity variables and no
  secret; the router compares keys with `hmac.compare_digest`;
  `_reconciled_cost` takes the larger of metered and ledgered spend;
  planning seats send `session_id`, not a task id; every retry loop is
  bounded.
- **Frontend.** No HTML injection sinks; `safeHref` everywhere;
  `useTaskStream` (socket-first hydrate, seq adoption, watchdog, backoff);
  lazy Monaco, recharts, Analytics and Benchmarks.
- **Dependencies.** `npm audit` and `pip-audit` report nothing on `main`.
- **Culture.** Incident-dated comments, a test per incident, a CHANGELOG
  that explains *why*, and three prior audits actually closed.
