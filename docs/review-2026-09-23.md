## 1. Security — the claim that is wrong

### 1.1 Host DB/e2e checks inherit `process.env`

**Severity:** critical on a host install that has `databaseCheck` configured.
**Files:** `services/commit-reviewer/reviewer.js` (`run`, `runSealed`,
`runDatabaseCheck`); `SECURITY.md` ("The database checks, which stay on the
host").

`run()` merges the full process environment:

```js
if (env) opts.env = { ...process.env, ...env };
```

`runSealed()` builds only `PATH` / `HOME` / `LANG` / `CI` /
`DEBIAN_FRONTEND` plus extras. Database checks (`db:drift`, `db:seed`,
`test:e2e`) call `run()`, not `runSealed()`.

The comment immediately above the three `run(...)` calls in
`runDatabaseCheck` says the env is "built here rather than inherited."
`SECURITY.md` says the same: "The environment is constructed for the run
rather than inherited, so the reviewer's own secrets are not in it."

Both are false. Agent-authored scripts on a host install inherit the
reviewer process environment (router keys, SMTP, whatever else is there).

**Shape of the fix**

- Route `dc.driftCmd` / `seedCmd` / `e2eCmd` through `runSealed()`, passing
  the throwaway `DATABASE_URL`, `REDIS_URL`, and the generated JWT/secret
  extras explicitly. `psql` / `redis-cli` admin calls can stay on `run()`
  only if they are not agent-authored — they still must not put the
  password on argv (`PGPASSWORD` is already the rule).
- Rewrite the `runDatabaseCheck` comment so it no longer claims the env is
  sealed if any leftover `run()` remains.
- Align `SECURITY.md` with the code the same day. If a sealed env cannot
  reach loopback Postgres/Redis without extra vars, name those vars. Do not
  leave the contradiction.
- Add a test that DB checks do **not** inherit `process.env` (a planted
  `OPENROUTER_API_KEY` / `REVIEW_CONTROL_SECRET` in the process env must
  not appear in the child). `tests/test_reviewer_sandbox.js` is the
  neighbourhood.

The residue itself (these three commands still run on the host, as root,
talking to loopback) stays documented. This item is the env lie, not the
accepted host-execution residue.

## 2. Security — authorization is a convention

### 2.1 `check_repo_access` is invisible to the route inventory

**Severity:** high (structural). No live route was found missing the call
on 2026-09-23. The next seam extraction is when this breaks.

**Files:** `agent/auth.py` (`check_repo_access`); `agent/server.py` (~20
call sites); `tests/test_route_inventory.py`; `docs/todo.md` (already
admits this).

The inventory pins FastAPI dependencies (`require_full_auth`,
`get_current_user`), not the in-handler `check_repo_access(user, repo)`.
A refactor can drop the call and every test stays green.

`auth.py`'s module docstring explains why it is manual: repo arrives in
enough different shapes (body, path, store lookup) that it is not a clean
`Depends`. That reason can stay. The safety net cannot.

**Shape of the fix**

- Extend `tests/test_route_inventory.py` (or a sibling) so every handler
  that touches a `repo` / `task_id` / `session_id` is listed, and the
  source of that handler must contain `check_repo_access` *or* be on an
  explicit allow-list with a reason (admin-only project CRUD, list
  endpoints that already filter by `list_visible_repos`, etc.).
- Prefer promoting `check_repo_access` to a dependency where the shape
  is already `repo: str` in the signature. Leave store-resolved task
  routes as an in-body call until that shape exists — but they must
  still appear in the snapshot.
- Do this **before** extracting `github` / `tasks` / `planning`.

### 2.2 `GET /api/router-balance` is any logged-in user

**Severity:** medium/high for a two-person box.

**Files:** `agent/server.py` (`get_router_balance`); frontend
`BalanceStrip` / sidebar credit display.

Requires `require_full_auth`, not `require_admin`. Proxies the
unauthenticated agent-review `GET /api/router/balance`. A restricted
account learns operator spend and remaining credit.

**Shape of the fix**

- `auth.require_admin(user)` on the handler, same as `/api/stats` and
  `/api/consolidation/status`.
- Hide or omit the sidebar credit chip for `role="user"`. Do not leave a
  chip that 403s in a loop.
- Inventory snapshot will need the guard name if you change the
  dependency; an in-body `require_admin` is the existing pattern on
  `/api/stats`.

## 3. Security — review services on the compose network

### 3.1 Agent-review read APIs have no secret

**Severity:** high in the bundle; accepted-on-loopback on a host install.

**Files:** `services/agent-review/server.js` — `GET /api/projects`,
`/api/projects/:name/status`, `/api/projects/:name/diff`,
`/api/router/current`, `/api/router/stats`, `/api/router/balance`,
`/api/review/status`. Mutating routes already use `requireControlSecret`.

On a host install these bind `127.0.0.1`. In the compose bundle
`TEKTONIX_BUNDLE=1` binds `0.0.0.0`. Any container on that network can
read diffs and project metadata. The agent sandbox has default bridge
egress. Those two facts belong in the same sentence.

**Shape of the fix** (pick one and write it in `SECURITY.md` first)

- Require the control secret (or the agent's session-proxy) on reads too;
  the console already goes through `/_review/{path}`, which injects the
  secret and refuses a caller-supplied `X-Review-Secret`.
- Or bind loopback-only in the bundle and isolate the sandbox network from
  `:4100` / `:4101`.
- Do not publish 4100/4101. That is already unpublished; do not "fix"
  reachability by publishing them.

Covered in spirit by `tests/test_review_proxy.py` (mutating path proves
secret injection). Add a case that a raw GET to the review service from
outside the proxy is refused *once reads are gated* — today it would
fail that assertion, which is the point.

### 3.2 Commit-reviewer `/health` names in-progress projects

**Severity:** high for recon, low for impact.

**Files:** `services/commit-reviewer/reviewer.js` control server
`GET /health` (returns `reviewing: [...inProgressProjects]`). Bundle binds
`0.0.0.0`.

`agent/health.py` only exposes `project_count`, never names. Match that
shape: a count, not a list, unless the caller presented the control
secret.

## 4. Security — approve links, 2FA, CSRF, rate limits

### 4.1 Approve-link tokens live in the URL

**Severity:** high for leak, residual after current mitigations.

**Files:** `agent/github_inbox.py` (`sign_approval` / `verify_approval`);
`agent/server.py` (`github_approve_page` / `github_approve_submit`).

HMAC, 48h, single-use, GET renders / POST acts — that part is correct.
The token still sits in `?t=`, Referer, proxy logs, chat previews, and
screenshots. A stolen unconsumed link starts work. Merge review still
holds the default branch (`_github_create_task`).

There is no `Sec-Fetch-Site` check on that POST. Agent-review mutating
routes already have one.

**Shape of the fix**

- Add the same `Sec-Fetch-Site` (or Origin) check the review dashboard
  uses. A messenger prefetch is GET and must stay inert.
- Rate-limit the POST by token and by IP (`agent/rate_limit.py`).
- Prefer consuming the token on a POST-only hidden field that is not the
  GET query string for the confirmation page's own form, if that can be
  done without breaking Telegram/email clients. If the `?t=` shape must
  stay, document the residue in `SECURITY.md` next to the other accepted
  risks rather than implying the signed link is leak-proof.
- Tests in `tests/test_github_inbox.py`: replay after consume, GET does
  not start a task, cross-site POST rejected.

### 4.2 2FA is admin-only; disable has no UI

**Severity:** medium (policy) + high (missing control).

**Files:** `agent/auth.py` `forced_screen_block` (only
`role == "admin" and not user.totp_enabled`); `agent/server.py`
`POST /api/auth/2fa/disable`; `frontend/src/api.ts` `disable2FA()`;
Settings UI — **no control**.

Documented: a `role="user"` password is enough for every repo they can
see. Fine for a household box. Weak the moment the second person is a
contractor.

`disable2FA` requires the current password (correct — a stolen session
must not drop the second factor). Settings never calls it. An admin who
enrolled and then loses the authenticator is in the database.

**Shape of the fix**

- Add a Settings control that calls `disable2FA(password)` and shows
  recovery-code / re-enroll guidance. Or, if disable-from-UI is
  deliberately refused, delete the unused client wrapper and say so on
  the Settings 2FA card ("disable is a database operation; see runbook").
- Do not silently start requiring TOTP for `role="user"` as part of this
  pass unless the operator asked. If you add it, it is a product decision
  and needs a migration story for existing user accounts.

### 4.3 CSRF on the session API is SameSite-only

**Severity:** medium. Correct for the current SPA. No token if cookie
flags ever loosen.

**Files:** `agent/server.py` `_set_session_cookie` (`SameSite=strict`,
`secure=True`); no CSRF tokens on POST. Approve-link POST is the
exception that does not have a session (item 4.1).

**Shape of the fix**

- Do not add CSRF tokens to every POST unless you are also loosening
  SameSite. Do add `Sec-Fetch-Site` on the approve-link POST (4.1).
- If a future change sets SameSite to lax or none, this item becomes
  blocking. Mention that coupling in the cookie helper comment if it is
  not already there.

### 4.4 Rate limits are in-memory and fail-open

**Severity:** medium on multi-worker; low on the current single-process

**Files:** `agent/rate_limit.py`. Login / reset limits die on restart and

**Shape of the fix**

- Do not silently fail open without a log line. A log already may exist;

**Files:** `agent/health.py`; commit-reviewer control `/health`.

## 11. Usability (product, not cleanup-by-default)

These are findings. Implement only where the item says to. Several are
product decisions.

### 11.1 No client router — cannot deep-link a task

**Files:** `frontend/src/App.tsx` — views are `useState`. No
`react-router`. No `/task/:id` or `/planning/:id`.

Refresh loses the selected pane except what the sidebar happens to
highlight. You cannot bookmark a task, send a teammate a session URL,
or recover a PWA launch onto the thing you were watching.

**Shape of the fix** (feature, after the server split is underway)

- Add a small router (or `window.location` + `popstate` if you refuse a
  dependency) for `/`, `/task/:id`, `/planning/:id`, `/inbox`,
  `/settings`, `/analytics`.
- Land on Planning when the path is `/`, matching the 2026-08-28
  plan-first decision.
- Do not take a URL dependency lightly; measure it. The review did not
  require react-router specifically.

### 11.3 `disable2FA` has no Settings control

See 4.2.

### 11.4 Windows compose has proven install, not task-through-merge

### 11.5 Install surface and four processes
